six-pack 流程速查

回看用的压缩版：忘了谁写 QA 规格、谁跑变异、卡片何时进 Done 时先翻这一页。对应课件：Lesson 0004。对照 four-pack。

合成

get-swarm-forge six-pack … = main 的 scripts + 三篇共享宪法 + pack 的 conf / roles / project.prompt / local-workflow.prompt / local-engineering.prompt。six-pack 的 swarmforge/ 本身没有 scripts。

拓扑

conf：specifier grok@master task · coder codex task · 后四岗 batch（cleaner / architect / hardender / QA）。以窗口行为准，不要被 project.prompt 的「全是 Codex」带偏。

启动时实际读什么

生成文件 .swarmforge/prompts/<role>.md：先递归读宪法文章，再读角色 prompt。six-pack 文章是 workflow / handoffs / engineering（main）+ project、local-workflow、local-engineering（pack）。全文中文在 0004 按调用顺序展开。

一轮

  1. specifier：Gherkin 五步 + UI 端到端 QA 规格 → 人批 → coder
  2. coder（验收管线 + TDD，忽略 QA 套件）→ cleaner
  3. cleaner（局部清理，scan/count，不跑变异）→ architect
  4. architect（只要结构 + 属性测试）→ hardender
  5. hardender（语言变异 → 软 Gherkin → CRAP → DRY）→ QA
  6. QA 把 QA 规格做成脚本，只从 UI 跑 → to: 其余五人 priority: 00＝末棒，卡片 Done
  7. 收到 QA 的人只验证（specifier 问下一张卡），不转发
