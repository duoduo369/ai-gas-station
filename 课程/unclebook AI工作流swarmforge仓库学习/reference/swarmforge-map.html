SwarmForge 速查地图

回看用的压缩版：忘了 main 和 pack 怎么分、卡片怎么走到 Done、共享宪法能不能被覆盖时，先翻这一页。对应课件：Lesson 0001。

先抓四个判断轴

1. main 是底座，pack 是流水线

main 放共享脚本和三篇核心宪法。可运行的 swarmforge.conf 与角色提示在 pack 分支。

2. swarmforge/ 三件套

宪法文章、交接协议、scripts。agent 不手写 tmux；helper + handoffd 才是通道。

3. 角色数 = 质量闸数

two-pack / four-pack / six-pack 按你要拆开多少个质量关注点来选，不按模型品牌。

4. 卡片跟着交接走

New Task 进 master 泳道；合法 git_handoff 移动卡片；最后一棒 to: 所有其他角色才进 Done。

main 上 swarmforge/ 怎么读

位置 当成什么 为什么重要
constitution/articles/ 共享法律 入口 constitution.prompt 在 pack 上（main 没有这份）。它要求读 articles/ 里每一个文件。三篇共享法只能从 main 来；全文在 0001。
handoff-protocol.md 给人的协议全文 audit、inbox 生命周期、task/batch 的权威说明。
scripts/ 启动与交接运行时 合成进每个角色 worktree 后进 PATH。
get-swarm-forge（仓库根） 合成器 main 共享件 + pack 覆盖/追加 = 可运行目录。

pack 角色链

Pack 链 Master 人类规格闸
two-pack coder → cleaner coder 无 specifier，交接直接送
four-pack specifier → coder → refactorer → architect specifier Attention 里 Approve / Reject
six-pack specifier → coder → cleaner → architect → hardender → QA specifier 同上

同名角色在不同 pack 里宽窄不同。two-pack 的 cleaner 几乎包办清理+架构+加固；six-pack 拆成 cleaner / architect / hardender。

每个角色一句话

角色 干什么 出现在
specifier 把意图写成 Gherkin / 验收标准 four、six
coder 按批准切片做 TDD 实现 全部 pack
cleaner 保行为清理；two-pack 还兼架构和变异 two、six
refactorer four-pack 的清理+属性测试支架 four
architect 模块边界与依赖方向；four 兼末棒变异 four、six
hardender 语言变异与软 Gherkin 变异 six
QA 把 QA 步骤做成脚本，从 UI 做末检 six

agent 日常三命令

  1. swarm_handoff.sh <draft> — 校验并排队发出
  2. ready_for_next.sh — 按 task 或 batch 接下工作
  3. done_with_current.sh — 结束当前项；MAIL_WAITING 就再 ready
