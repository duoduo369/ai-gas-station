术语速查

后续课件沿用这里的叫法。角色与编排词压缩自仓库 README 和 pack 提示；BDD / Gherkin / CRAP 是行业通用概念，下面单独展开并给例子。git_handoff 是本项目的交接格式。对应课件：0001 · 0002 · 0003 · 0004。

角色（工种）

术语 在本课里指什么
specifier 规格员。把用户意图写成 Gherkin 和验收标准；four/six 的 master。交出后等人在 Attention 批准。
coder 实现员。按已批准切片做 TDD 实现；two-pack 的 master。不跑 CRAP / DRY / 变异测试。
cleaner 清理员。保行为、收拾代码。two-pack 还兼架构和变异加固；six-pack 只做局部清理，不跑变异测试。
refactorer 重构员。仅 four-pack。接近 six-pack 的 cleaner，外加属性测试支架；不引入新功能。
architect 架构员。模块边界与依赖方向（高层不依赖 IO）。four-pack 兼变异、是末棒；six-pack 改完结构交给 hardender。
hardender 加固员。仅 six-pack。语言变异 + 软 Gherkin 变异，再复查 CRAP/DRY。
QA 验收员。仅 six-pack。把 specifier 的 QA 步骤做成脚本，从 UI 跑端到端；末棒全员交接进 Done。

编排与工程词

术语 在本课里指什么
pack 一条可运行工作流分支：two-pack、four-pack 或 six-pack。
main 纪录片分支：共享 scripts 与三篇核心宪法，不是完整项目工作流。
constitution 分层法律。入口是 constitution.prompt，条款在 constitution/articles/。
local-*.prompt pack 对共享条款的叠加或收窄，禁止用同名文件覆盖共享篇。
role swarmforge.conf 里的一个窗口/工种，对应 roles/<role>.prompt。
master agent worktree 名为 master 的角色；New Task 和聊天只找它。
质量闸 单独拆成一个角色的质量关注点。闸的数量决定选哪个 pack。
BDD 行为驱动开发：先写可观察行为，再自动化验证。Gherkin 是常用写法。详见下方。
Gherkin BDD 常用的规格语言（Given / When / Then）。本仓库走 APS。详见下方。
CRAP 改代码风险 = 复杂度 × 缺测试。本仓库目标 ≤ 6。详见下方。
git_handoff 本项目交接格式：四行头指向一次 commit。详见下方。
TDD 先写会失败的聚焦单元测试，再写刚好够过的产品代码。
DRY 宪法指定的重复检测工具，用来减有意义的重复。
变异测试 故意改程序，看测试会不会抓住；抓不住的 survivor 要被补测试或改设计杀死。
worktree 同一仓库的另一份工作目录。非 master 一般在 .worktrees/<name>。
note 一行短消息交接。默认不要发，除非用户、角色或宪法明确要求。
handoffd 守护进程：搬文件、发通用唤醒，独占 tmux socket 访问。
task / batch 接收模式。task 一次一项；batch 把当前同等优先级的交接打成一批。
Attention 仪表盘上等人批规格或回答澄清的区域。
pack cockpit 本地仪表盘：New Task、Attention、泳道看板、Work Queue、聊天、Teardown。
tmux 终端会话复用器；agent 跑在项目专用 tmux 里。
window-invisible 角色只在 tmux 里跑，不弹 Terminal。pack 默认。
末棒广播 最后一角色的 git_handoff，to: 为每一个其他角色。two-pack 里就是 cleaner → coder。卡片因此进 Done。

BDD（通用概念）

BDD = Behavior-Driven Development（行为驱动开发）。Dan North 在 2000 年代前后把 TDD 往「用业务能读懂的语言描述行为」推了一步：测试不再只写「这个函数返回什么」，而是写「系统在某种情况下应该怎样表现」。Cucumber 文档把 Gherkin 称为 BDD 的「通用语言」；Martin Fowler 把 Given / When / Then 称为 BDD 里常用的规格结构（见 GivenWhenThen）。

和本课里其它词的关系，可以这样记：

词 管什么 典型写法
TDD 一小块产品代码该怎么通过测试 单元测试（coder 在 SwarmForge 里默认这么做）
BDD 对外可见的行为对不对 场景化描述 + 可执行的验收测试
Gherkin BDD 场景的一种文件格式 .feature 里的 Feature / Scenario / Given / When / Then

four/six-pack 里两套一起用：specifier 用 Gherkin 写验收规格（外面看得见的行为），coder 仍用 TDD 写单元测试（里面怎么实现）；engineering 宪法也写明：生成的验收测试不能代替单元测试。two-pack 连 Gherkin 都关掉，只剩 coder 的 TDD + cleaner 的质量工具。

一句话例子：TDD 可能测「hashPassword 对同一输入总得到同一摘要」；BDD（Gherkin）会写「用户在登录页输入正确密码后，应进入首页」。后者不关心你用的是 bcrypt 还是别的，只关心用户能观察到的结果。

Gherkin（通用概念）

Gherkin 是 Cucumber 一系 BDD 工具用的领域语言（不是编程语言）：用接近自然语言的句子描述BDD里的可观察行为。权威结构见 Cucumber Gherkin Reference。

最小例子（登录）：

Feature: 用户登录

  Scenario: 用正确账号登录
    Given 用户停在登录页
    When 用户输入有效的邮箱和密码
    Then 用户应被带到首页

带例子表（同一场景多组数据）时，会写成 Scenario Outline + Examples。Fowler 文中的股票例子更长：先 Given 持仓和开市，When 卖出，Then 持仓和委托都对得上。

在 SwarmForge 里还多一层： 规格必须符合 Acceptance Pipeline Specification。agent 用 gherkin-parser 把 feature 变成 IR，再用 gherkin-mutator 去改例子值，看验收测试会不会抓住。所以 specifier 会被要求：可变字段写成参数、删掉不能改善变异的相同列。two-pack 的 project.prompt 整段关掉 Gherkin；four/six-pack 打开。

CRAP（通用概念）

CRAP = Change Risk Anti-Patterns（也有文献写成 Change Risk Analysis and Prediction）。Alberto Savoia 与 Bob Evans 在 2007 年前后提出：一段函数「改起来有多危险」，由圈复杂度和自动化测试覆盖率一起决定。原始说明见 Pardon My French, But This Code Is C.R.A.P.。Uncle Bob 后来在 crap4java 等工具里沿用同一公式。

公式（覆盖率写成 0–1 的小数）：

CRAP = CC² × (1 − coverage)³ + CC

直觉：

  • 覆盖率 → 100% 时，公式退化成 CRAP = CC：再复杂也有测试护着，但复杂本身仍有改动风险。
  • 覆盖率 → 0 时，近似 CC² + CC：没测试时，复杂度平方放大风险。

数字例子（同一函数 CC = 10）：

覆盖率 CRAP 怎么读
100% 10 只剩复杂度本身
50% 10²×0.5³ + 10 = 22.5 缺测开始发力
0% 110 先补测试，再考虑拆函数

门槛各家不同：早期 crap4j 常用 30；crap4java spec 默认超过 8.0 失败。SwarmForge 清理岗（two-pack cleaner、four-pack refactorer、six-pack cleaner）写的是把 CRAP 降到 6 或以下，比上述默认更严。工具必须用宪法表里的 crap4clj / crap4go / crap4java，不要自制 bb crap。

git_handoff（本项目概念）

git_handoff 是 SwarmForge 规定的一种交接消息类型：载荷是发送方 worktree 上已经提交的 HEAD。完整协议在 handoff-protocol.md；agent 日常跟的是 handoffs.prompt。

agent 只准写四行头，SHA 由 helper 填：

type: git_handoff
to: cleaner
priority: 50
task: add-login

之后它跑 swarm_handoff.sh ./tmp/草稿。下游被唤醒后跑 ready_for_next.sh，helper 把那个 commit merge 进自己的 worktree。看板卡片用同一个 task: 名字跟着跳泳道。

对比：note 也是交接，但只有一行 ≤80 字符的 message:，默认禁止发。末棒那一次 to: 必须列出每一个其他角色（例如 six-pack 的 QA 列五个人），卡片才进 Done。
