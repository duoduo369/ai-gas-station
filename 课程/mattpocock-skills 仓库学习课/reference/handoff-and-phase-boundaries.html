handoff 与 phase boundary 速查

忘了 `handoff` 到底是什么时，先抓一句：它首先是一个可携带交接文档，不是自动结束当前 session 的开关。这页用来快速对照 `handoff`、`/clear`、`/compact`、subagent 的边界。

一句话区分

`/handoff`

生成 portable markdown 文档，给另一个 agent、另一个目录、另一个 harness 或旁支任务接手用。

`/clear`

清空当前窗口，适合当前上下文对下一步完全无关时使用。

`/compact`

把当前 session 压成总结再继续，适合相关上下文仍重要但窗口快满时。

Subagent

把一个你暂时不用盯着的小范围任务外包出去，当前 session 保持不变。

为什么 `/handoff` 后 agent 还会继续

因为 `handoff` skill 原文只要求“写一份 handoff document 并保存到系统临时目录”，并没有要求“写完后必须停止当前 session”。

所以它默认是一个“产物动作”，不是“终止动作”。如果你在当前窗口里调用它，agent 很可能会在生成文档后，继续响应你当前窗口后面的目标，除非你明确把当前窗口停在这里或转去新的窗口。

什么时候真的该用 `/handoff`

场景 为什么是 handoff
换 harness 比如 Claude 和 Codex 之间切换，需要可携带的文档作为桥。
换目录或仓库 因为上下文不只要“压缩”，还要能带走到别的地方。
交给同事或另一位 agent 因为目标是让别人接手，而不是你自己继续。
中途分叉一条侧任务 当前主线不想被打断，但旁支需要一份可独立运行的起始材料。

什么时候不该把 handoff 当成默认动作

你其实还能继续

如果下一阶段还需要当前 session 作为 primary source，按 phase boundaries 的顺序，第一反应应该是 Continue。

你只是想换一个干净窗口

那更像 `/clear` 或 `/compact` 的问题，不一定需要 portability。

你期待的是“调用完立刻切走”

这是一种 harness 体验期待，不是 `handoff` skill 文本本身承诺的行为。
