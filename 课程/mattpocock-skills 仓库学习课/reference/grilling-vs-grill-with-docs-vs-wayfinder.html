grilling / grill-with-docs / wayfinder 对照表

忘了三者怎么选时，不要先回忆术语，先问四件事：我现在是在做原语级追问，还是在带文档地磨清一个想法，还是在给巨大而有雾的项目先找路？这页是给这种判断用的。

一句话区分

grilling

最底层的访谈原语。核心是 design tree、frontier、按 round 追问。

grill-with-docs

把 `grilling` 放进工作目录，并同步拉起 `domain-modeling`，让澄清结果留下 glossary / ADR 之类的文档痕迹。

wayfinder

当工作大到一个 session 装不下时，基于 `grilling` 和 `domain-modeling` 先建 decision map，而不是直接把它写成 spec 或开始实现。

怎么选

问题状态 更像谁 为什么
我只想把一个计划或想法问清楚 grilling 此时你要的是追问机制本身，不一定需要工作目录文档或 issue map。
我在工作目录里，要把一个可在单个 session 里 hold 住的想法磨清楚 grill-with-docs 它仍然是 grilling，但会把结果沉淀进 `CONTEXT.md` / ADR，而不是只停在对话里。
目标太大、有雾、要跨多个 session，连路线都还没看清 wayfinder 它不是先做 spec，而是先建 map，把 fog、frontier、decision tickets 排出来。

和 to-spec 的关系

`wayfinder` 清图之后，按设计会 hand off 到 `to-spec`；`grill-with-docs` 不一定。

`wayfinder` 解决的是“先找路”，所以地图清楚之后需要有人把那些 linked decisions 折叠成 buildable plan，这就是 `to-spec` 的位置。`grill-with-docs` 则是主流程默认起点：如果工作要跨多个 session，接 `to-spec`；如果范围足够小，也可以直接进 `implement`。
