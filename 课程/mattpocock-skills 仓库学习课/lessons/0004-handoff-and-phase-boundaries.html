Lesson 0004

把 handoff 和“结束当前 session”拆开理解

这一课专门解决一个很容易踩坑的误解：你可能以为 `/handoff` 的本质是“切走当前上下文”，但从 skill 原文看，它首先是“生成一份可携带的交接文档”。这两个动作经常在实际使用里被混成一个东西。

预计 14 分钟 目标：会判断 handoff 什么时候该用 速查：handoff 速查

先抓一条最重要的纠偏

`/handoff` 默认是“产物动作”，不是“终止动作”。

`handoff` skill 的定义很短也很直接：写一份 handoff document，总结当前对话，保存到系统临时目录，并给下一位 agent 一个 suggested skills 区段。它没有写“写完后必须结束当前 session”或“写完后自动切换到新窗口”。

原文：handoff/SKILL.md · 整份 skill 只承诺写文档。phase boundary 的五选一顺序树已嵌在 0002，本课不重复。

---
name: handoff
description: 把当前对话压缩成一份交接文档，供另一位 agent 接手。
argument-hint: "下一次会话将主要用来做什么？"
disable-model-invocation: true
---

写一份 handoff 文档，总结当前对话，让一个全新的 agent 可以继续这项工作。把文件保存到用户操作系统的临时目录，而不是当前工作区。

文档中要包含一个 “suggested skills” 小节，建议 agent 应该调用哪些 skill。

不要重复其他产物里已经记录过的内容（例如 specs、plans、ADRs、issues、commits、diffs）。改为用路径或 URL 引用它们。

删去任何敏感信息，例如 API key、密码或可识别个人身份的信息。

如果用户传入了参数，就把它当作“下一次会话将聚焦什么”的描述，并据此调整这份文档。

为什么你会觉得它“应该不污染当前 session”

因为 handoff 的直觉语义像“交棒”

一听到 handoff，很自然会联想到“我交出去就不在这里继续了”。这是非常合理的期待。

但 skill 文本只承诺了文档

它承诺的是把当前上下文压成一份 portable markdown，给下一位 agent 用；并没有承诺当前 agent 在这个窗口里停止思考或停止响应。

所以“继续工作”其实不违背定义

如果你在当前 session 里又给了后续目标，或者 harness 仍把这个窗口视为主会话，agent 继续做下去在定义上是说得通的。

phase boundary 里，handoff 只是五选一中的一个

选项 解决的核心问题 是否强调 portability
Continue 还能不能继续留在当前 session 否
/clear 当前上下文是不是完全无关 否
/handoff 需不需要一份能带去别的 harness / 目录 / 人的文档 是
Subagent 这块任务能不能外包出去 部分
/compact 需要保留总结但要换一个更轻的窗口 否

这张表里最该记的是：`/handoff` 解决的是 portability，不是“结束当前会话”本身。 五个选项怎么按顺序问，见 0002 的 PHASE-BOUNDARIES 中文全文。

所以 handoff 应该怎么用

换 harness

比如你想从一个 agent 环境切到另一个环境，这时需要一份 portable 文档作为桥。

换目录或仓库

因为新环境不共享当前 session 的上下文，所以 handoff 的价值一下子变高。

交给别人接手

无论是同事还是另一位 agent，都需要一个“拿起来就能继续”的起点文件。

主线中途分叉

你不想让当前窗口被旁支任务污染，但旁支又需要一份上下文起点，这时 handoff 很合适。

你遇到的现象，应该怎样理解

你输入“`/handoff` + 一段描述”时，这段描述默认是在告诉 agent：请按这个下一阶段焦点来定制 handoff 文档。

它不等于“请你现在立刻跳去那个下一阶段”。如果当前窗口里没有额外机制去切走，新 agent 也没有自动被创建，那么当前 agent 继续在原窗口里响应，是完全可能的。

更直白地说：`/handoff 做 X` 通常表示“为下一位做 X 的 agent 生成一份交接文件”，而不是“你自己现在开始在另一个上下文里做 X”。

如果你的目标真的是“不污染当前 session”

目标是完全丢弃当前上下文

更像 `/clear`。

目标是保留总结但换轻量窗口

更像 `/compact`。

目标是把任务转移给别处

这时才是 `/handoff` 真正不可替代的位置；但你通常还需要手动去打开新 session、或明确停在这里。

3 分钟自测

1. `/handoff` 默认最核心的产物是什么？

2. 在 phase boundary 里，`/handoff` 最独特的价值是什么？

3. 你在当前 session 里调用 `/handoff` 后，agent 是否一定会停止当前窗口里的工作？

这一课结束时，你应该能说出的 4 句话

1. handoff 是产物

默认首先是 portable handoff document，而不是会话终止器。

2. 终止当前 session 是另一件事

需要不要继续、要不要 clear、要不要 compact，是 phase boundary 的另一层判断。

3. handoff 真正解决 portability

换 harness、换目录、交给别人、分叉旁支，这些都需要它。

4. `/handoff 做 X` 不等于“现在就切去做 X”

更常见的含义是“请为下一位做 X 的 agent 生成一份交接文档”。
