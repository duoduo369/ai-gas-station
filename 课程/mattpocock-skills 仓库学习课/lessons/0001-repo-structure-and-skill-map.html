Lesson 0001

先建立这个仓库的地图感

这一课只做一件事：帮你把 mattpocock-skills 看成一个有清晰分层的技能仓库，而不是一堆零散的 SKILL.md。学完后，你应该能说清它的目录结构、主要分桶、两条分类轴，以及主流程是怎么串起来的。

预计 8 分钟 目标：建立全局地图 回看资料：速查地图

先记住一句总判断

这个仓库不是“一个超级技能”，而是一套可组合的小技能系统。

所以你理解它的关键，不是逐字背每个 skill，而是先认出它用什么方式把 skills 组织起来：先分 bucket，再分调用方式，再放进一条或几条 flow 里。这个判断来自仓库总览和 `ask-matt` 的流程描述。

第一层：顶层结构在说什么

README.md 是总入口

先讲“为什么会有这套 skills”，再讲安装方式、项目哲学和技能总表。你第一次看项目时，这里负责建立全局感。

CLAUDE.md 是维护规则

它告诉你 bucket 怎么分、哪些 skill 算 promoted、以及 README、docs、插件 manifest 之间必须保持怎样的同步。

skills/ 才是主内容区

真正的 skill 都在这里，而且不是随便平铺，而是分到 `engineering`、`productivity` 等五个桶里。

plugin.json 是发布视角

它不是教学文档，而是最直接的“出货清单”：哪些 skill 真会进 Claude 插件，一眼就能看到。

第二层：先看 bucket，再看单个 skill

Bucket 你可以怎么理解它 当前读法
engineering 工程主线技能 和“从想法到交付”的流程最相关，优先看。
productivity 通用协作技能 像 `teach`、`handoff`、`wait-what` 这种跨场景能力在这里。
misc 保留区 知道它存在即可，不把它当主航道。
in-progress 公开试验区 适合观察新方向，但不当稳定接口。
deprecated 退役区 知道它被放弃了，比精读更重要。

这里最值钱的判断不是名字本身，而是 promoted buckets 只有两个：`engineering` 和 `productivity`。这两个桶必须进顶层 README，也必须进插件 manifest；其他三个桶不能混进去。

第三层：再抓第二条分类轴

user-invoked

只有用户明确输入时才会走到。它们通常承担“编排流程”的职责，比如 `/ask-matt`、`/grill-with-docs`、`/teach`。

model-invoked

模型自己也可以在合适时机调用。它们更像可复用的底层 discipline，比如 `tdd`、`code-review`、`grilling`。

一个很实用的记忆法是：user-invoked 更像“入口和流程”，model-invoked 更像“方法与约束”。

第四层：用 ask-matt 把主线串起来

主线是：idea → grill-with-docs → to-spec → to-tickets → implement

`ask-matt` 最有价值的地方，是它不只是告诉你“仓库里有什么”，而是告诉你“这些 skill 在什么时候接力”。这就是为什么它像路由器，而不是单纯索引。

triage

当工作从外部 issue 涌进来，不是你自己发起的想法时，先 triage 再并回主线。

diagnosing-bugs

当问题是“出 bug 了”，先建立能可靠变红的反馈回路，再谈修复，而不是直接凭感觉改。

wayfinder

当工作大到一个 session 装不下时，先做决策地图，等 fog 被推开后再回到主线。

3 分钟自测

先不追求全懂，只检查你有没有抓住最关键的判断轴。

1. `teach` 默认属于哪类调用方式？

2. `misc` 里的 skill 对顶层 README 和插件清单来说应该怎样？

3. 一个多轮次的大功能构建，在进入 `implement` 前更推荐哪一步？

这一课学完，你至少该带走什么

1. 这是组合系统

重点不在某一个“神技”，而在 skills 之间的接力关系。

2. 先抓两条轴

先分 promoted / non-promoted，再分 user-invoked / model-invoked。

3. ask-matt 是地图

它把 README 里的 skill 列表变成了“何时用谁”的流程图。

下一步怎么学最顺

建议你下一课继续学这三个点中的一个：

  1. 精读 `ask-matt`，把主流程和各个 on-ramp 真正串熟。
  2. 挑一个 user-invoked skill 看它怎么编排底层 skills，例如 `grill-with-docs` 或 `teach`。
  3. 挑一个 model-invoked skill 看“方法论是怎么被封装的”，例如 `grilling`、`tdd` 或 `code-review`。

如果你愿意，我下一轮可以直接带你进 `ask-matt`，把它拆成一张更细的流程图。

主资料

这一课最值得你亲自读的主资料是 ask-matt/SKILL.md。原因很简单：README 告诉你“这里有什么”，但 `ask-matt` 告诉你“什么时候该走哪条路”。

  1. README.md
  2. CLAUDE.md
  3. skills/engineering/README.md
  4. skills/productivity/README.md
  5. skills/engineering/ask-matt/SKILL.md
  6. .claude-plugin/plugin.json
  7. package.json
