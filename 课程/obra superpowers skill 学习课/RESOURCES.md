# Superpowers Resources

## Knowledge

- [Repository: README.md](https://github.com/obra/superpowers/blob/main/README.md)
  仓库总入口。用来建立项目目标、安装入口、七步基本工作流和核心技能全貌。
- [Skill: using-superpowers/SKILL.md](https://github.com/obra/superpowers/blob/main/skills/using-superpowers/SKILL.md)
  “先找 skill，再行动”的硬门槛。用来理解 Superpowers 为什么先管方法，再管执行。
- [Skill: brainstorming/SKILL.md](https://github.com/obra/superpowers/blob/main/skills/brainstorming/SKILL.md)
  设计阶段总入口。用来理解请求分类、审批门槛，以及为什么不能边讲边做。
- [Skill: writing-plans/SKILL.md](https://github.com/obra/superpowers/blob/main/skills/writing-plans/SKILL.md)
  计划生成规则。用来理解任务怎样被拆成可执行、可验证、可交接的小步。
- [Skill: using-git-worktrees/SKILL.md](https://github.com/obra/superpowers/blob/main/skills/using-git-worktrees/SKILL.md)
  隔离工作空间规则。用来理解 worktree 为什么属于实现 / 调试的环境层，而不是后置彩蛋步骤。
- [Skill: subagent-driven-development/SKILL.md](https://github.com/obra/superpowers/blob/main/skills/subagent-driven-development/SKILL.md)
  SDD 的完整执行环。用来理解“每个任务怎么推进、怎么 review、怎么 fix loop、怎么进入最终收口”。
- [Skill: executing-plans/SKILL.md](https://github.com/obra/superpowers/blob/main/skills/executing-plans/SKILL.md)
  非 SDD 情况下的执行模式。用来理解它和 SDD 的边界，以及为什么它更强调遇阻即停。
- [Skill: test-driven-development/SKILL.md](https://github.com/obra/superpowers/blob/main/skills/test-driven-development/SKILL.md)
  实施纪律底座。用来理解 README 里的 TDD 主张在 skill 层是怎么被具体化的。
- [Skill: requesting-code-review/SKILL.md](https://github.com/obra/superpowers/blob/main/skills/requesting-code-review/SKILL.md)
  review 规则卡。用来理解为什么 review 是 mandatory gate，而不是“看心情补一个”。
- [Skill: receiving-code-review/SKILL.md](https://github.com/obra/superpowers/blob/main/skills/receiving-code-review/SKILL.md)
  接 review 后的响应规则。用来理解“review 指出缺口时应该先验证、先澄清、还是直接实现”。
- [Skill: systematic-debugging/SKILL.md](https://github.com/obra/superpowers/blob/main/skills/systematic-debugging/SKILL.md)
  调试规则卡。用来理解验收 bug / 失败测试 / 异常行为时为什么必须先找根因，再提修法。
- [Skill: verification-before-completion/SKILL.md](https://github.com/obra/superpowers/blob/main/skills/verification-before-completion/SKILL.md)
  完成前验证门槛。用来理解为什么 agent 报 success 不等于真的满足 spec 或真的修好 bug。
- [Skill: finishing-a-development-branch/SKILL.md](https://github.com/obra/superpowers/blob/main/skills/finishing-a-development-branch/SKILL.md)
  正式收口规则。用来理解合并、提 PR、保留分支、discard、cleanup 的边界。
- [Codex Plugin Manifest: .codex-plugin/plugin.json](https://github.com/obra/superpowers/blob/main/.codex-plugin/plugin.json)
  从 Codex 视角理解这个仓库是如何被包装成插件的，以及对外描述强调了哪些能力。

## Wisdom (Communities)

- [Superpowers Discord](https://discord.gg/35wsABTejz)
  README 里给出的社区入口。适合提问、观察别人怎么使用这套方法，以及验证自己的理解是不是停留在纸面。
- [GitHub Issues](https://github.com/obra/superpowers/issues)
  适合看真实问题、设计权衡和用户反馈，帮助理解技能体系在哪些地方最常被讨论。

## Gaps

- 仓库里没有一页专门面向学习者的总图，课程里的 `reference/` 需要承担这部分压缩整理。
- 不同 harness 的行为差异分散在多个目录和文档里，等建立完主流程地图后再单独开课会更稳。
