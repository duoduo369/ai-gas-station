WorkBuddy skill 结构速查

回看这一页就够了。先抓 WorkBuddy 的最小骨架，再看它和 OpenAI Skills、Claude Code Skills 分别有什么区别。

lesson：0001 结构对照课

先抓四个结论

  • WorkBuddy skill 的最小单位不是一句 prompt，而是一包文件：SKILL.md 在中间，references / scripts / templates 在旁边；真正提交到开放平台时，还要把这包内容打成 zip。
  • WorkBuddy 文档把 frontmatter 字段单独钉住了，尤其要求 description、description_zh、description_en、version、author。
  • 像 writing-for-agents 这样的 skill 不是另一种平台格式，它们在写法层帮你决定 description 怎么触发、正文和 reference 怎么分层。
  • OpenAI Skills 更像“API 里挂一个版本化文件包”，Claude Code Skills 更像“本地开发环境里的按需流程扩展”。

WorkBuddy 的最小骨架

my-skill/
├── SKILL.md
├── references/
│   └── best-practices.md
├── scripts/
│   └── tool-index.js
└── templates/
    └── report-template.md

WorkBuddy 这页文档真正固定的，是 SKILL.md 和三类子目录。正文里写步骤，知识补充下沉到 references/，运行时逻辑放 scripts/，模板骨架放 templates/。真正提交到开放平台时，再把这一整包目录打成 zip。

Frontmatter 速查

字段 是否必填 你该怎么理解
name 否 技能标识。没有也能成立，但通常还是会写。
description 是 写清用途和触发词。这里最值得借 writing-for-agents 这类 skill 来压缩上下文负担。
description_zh / description_en 是 WorkBuddy 比较突出的地方：它把中英双语简介也当成结构的一部分。
allowed-tools 否 工具白名单。
version 是 版本号。
disable-model-invocation 否 true 时不自动触发，只能手动调。
user-invocable 否 false 时对用户隐藏，只给 AI 内部用。
author 是 合作方名称。

三家对照

问题 WorkBuddy OpenAI Skills Claude Code Skills
skill 主单位 SKILL.md + 固定子目录 版本化文件包 + SKILL.md manifest .claude/skills/<name>/SKILL.md
模型先看到什么 frontmatter，尤其三段 description name / description / path 技能名和描述
支持文件组织 文档直接点名 references / scripts / templates 文件包自由放，没固定目录名 skill 目录里自由放文件，还能动态注入上下文
skill 外的边界 这页文档没展开 更偏 API 挂载层 长期规则进 CLAUDE.md，专门 worker 另走 subagents

写卡时怎么用 writing-for-agents

description 先写触发分支

别先写自我介绍，先写什么情况该触发这张卡。

正文只留每次都要执行的步骤

每条分支都要读的，留在 SKILL.md。只部分场景才用的，再下沉。

知识和执行分开

静态知识进 references/，真的要跑的逻辑才进 scripts/。

模板别假装是脚本

只负责复用骨架、不负责运行的，才放 templates/。
