教学工作区

把当前目录当成教学工作区。学习状态落在这些文件里：

  • MISSION.md：你为什么对这个主题感兴趣。所有教学都挂在这份理由上。
  • ./reference/*.html：从课时里压出来的材料。小抄、算法、语法、体式、术语表。给打印和快速回看。
  • RESOURCES.md：用来垫上下文知识，或去拿知识和智慧的资料清单。
  • ./learning-records/*.md：你已经学会了什么。记下非显然的课和关键洞察，用来计算最近发展区。
  • ./lessons/*.html：课时。一节课是一份自包含 HTML，只教一件和使命绑死、范围很紧的事。
  • ./assets/*：跨课时复用的组件。
  • NOTES.md：教学偏好和工作备忘。

哲学

要学到深处，你需要三样东西：

  • Knowledge：从高质量、高信任的资料里拿到。
  • Skills：靠基于这些知识设计的、高度相关的互动课练出来。
  • Wisdom：来自和其他学习者、实践者的互动。

RESOURCES.md 还没填满之前，先去找能帮你拿到知识的高质量资料。不要信模型参数里那点东西。有的主题知识比技能多，比如理论物理。有的主题技能比知识多，比如瑜伽。

流畅强度 vs 存储强度

  • Fluency strength：当下能把知识想起来。
  • Storage strength：长期还留着。

流畅会给你一种已经会了的错觉。真正要的是存储强度。课要靠合意难度把长期记忆建起来：提取练习、间隔、交错。交错只用于技能练习。

使命

每节课都要挂在使命上：你为什么要学这个。使命不清楚，或 MISSION.md 还是空的，第一件事是问你为什么要学。使命没钉住，知识会飘，课会抽象，下一课也没有判断标准。

使命会改。改之前先跟你确认，再更新 MISSION.md，并补一条学习记录。

最近发展区

每节课都该让你觉得“刚好有点难”。你点名要学某件具体的事，就教那件。你没点名，就读 learning-records，对着使命选最相关、又刚好卡在最近发展区里的那一件。

知识

课围着你将要学会的一项技能来设计。课里的知识只放练这项技能需要的那部分。先教知识，再让你在紧反馈环里练技能。

知识先从受信任的资料里收集，记进 RESOURCES.md。课里的判断要带外链。学知识时，难度是敌人。它会吃掉你用来理解的工作记忆。

技能

技能要的是耐用和能迁移，让知识站住。

练技能时，难度是工具。费力提取才能长出存储强度。互动课、测验、轻量的页内任务、真实步骤清单，都要有尽量短的反馈环。测验的每个选项，词数要一样，字符数能一样更好。不要用排版给答案通风报信。

参考文档

写课的同时写参考页。课很少回头看，参考页会。它们是课时的压缩精华，做成快速查阅。术语表一旦建了，后面每课都要守它。

空目录里，课按这个顺序走

1

先问为什么学

使命空着就写课，后面每课都缺锚点。人读 docs 把“先访谈、再出课”写成它在工作的第一条信号。

2

RESOURCES.md 先于 lessons

SKILL.md 写得很直：资料没填满之前，先去找资料。一课没有引用，就是在用模型记忆教书。

3

写出一节能上完的 HTML

一课一事，挂在使命上，推荐一份主资料，提醒你不懂就问这个当老师的 agent。

4

把精华压进 reference

语法表、流程图、术语，从课里抽出来。以后回看走速查，不把整节课再读一遍。

下一课从文件夹续，不从聊天记录续。人读 docs 说三种做法都行：同一会话接着要下一课、新会话再打 /teach、在同一文件夹开新会话说“下一课”。文件夹才是连续性。做法：在工作区开新会话，打 /teach next lesson，后面再补主题。

斜杠后面可以跟什么

SKILL.md 的 argument-hint 是 What would you like to learn about?。斜杠不是只能光秃秃打出去：主题可以写在同一条消息里。

你打的 它当什么用
/teach 空目录里该先问为什么学。你还没给主题，就让它问。
/teach 尤克里里弹唱 主题直接当参数。日常技能和编程主题，走同一套工作区。
/teach https://github.com/obra/superpowers 或 /teach obra/superpowers 把这个仓库当学习对象。人读 docs 说，代码侧最稳的用法是摸不熟的代码库，不是从零学一门语言。
斜杠后面再写一段约束 已知、缺口、指定资料、目录落点、不要选择题，都可以写在第一句。第一课没有摸底（#725），起始水平靠你自己报。

先开一个只给这门课用的目录，再打斜杠。

续课

同一文件夹开新会话：/teach next lesson。人读 docs 写过，课是一次一次唤，连续性在文件夹，不在聊天窗口。

纠水平

「这课太深，我还不会 X」「我已经会 Y，记进 learning-records，别再教。」纠正会变成记录，下一课才转得过来。

要复习，不要新课

它会做下一课，不太会自己改去复习。想对着琴/代码练，就明说：不要新 HTML，先按 reference 出一组练习步骤。

改资料、改偏好

「主资料换成这个链接」「以后中文、短课、不要选择题」写进 NOTES.md。偏好不说，它不会猜到。

三个还没修好的坑

文件写进 skill 安装目录

#377：SKILL.md 里的 ./ 同时指 skill 包和你的工作区。第一节课落地后先看路径。开始时把目录说死。

正确答案总在第一项

#335 还在。选项字数对齐能挡住另一种泄题，挡不住位置。上游 teach 若坚持出测验，不要把第一项当答案。

第一课没有摸底

#725 还是功能请求。起始水平靠你自己说，或靠空的 learning-records/。第一句就把已知和缺口讲清楚。

人读 docs 还有一句更硬的：teach 不可未经核对就信。有人学二阶魔方时拿到了编出来的公式。手续领域、记号一错就错的主题，风险最高。代码这种立刻能跑的，风险低一些。每课那份主资料是给你去核对的，不是装饰。

这一课学完，你至少该带走什么

1. 自己打 /teach

agent 不会自己走这张卡。学习是项目时才用；当场要一句解释，直接问。

2. 连续性在文件夹

使命、资料、课件、速查、学习记录都是文件。新会话打开同一目录，课就能续。

3. 回看走 reference

lesson 负责第一次学会。以后翻速查，不把整节 HTML 再读一遍。

4. 本库还要套 teach-me

这部分在 0001 已经先讲完。课放进 课程/某课/，chrome 放在该课 assets/。精读课才嵌条文。

5. 第一句把用法说死

主题、GitHub 地址、已知和缺口、指定资料、目录落点，都写在同一条 /teach 里。空着打出去，它只能猜。

主资料

这一课请你自己去读的主资料是人读说明 docs/productivity/teach.md。它比 SKILL.md 更适合你当使用者看：何时伸手、常见坑、怎样判断它在工作。agent 执行时读的仍是 SKILL.md。
