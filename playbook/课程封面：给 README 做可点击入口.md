# 课程封面：给 README 做可点击入口

> 给要把课程放进知识库 `README.md`、并希望入口更抓眼球的 Agent / 人用。
> 这条不是单次 Prompt 备份，而是“如何稳定产出同系列课程封面”的方法卡。

## 核心目的

当 `README.md` 里已经有多门课程，只放文字链接往往不够醒目。

这时可以把课程入口改成“**可点击封面 + 标题链接**”的形式：

- 封面先负责吸引点击
- 图片本身就是课程入口
- 多门课维持同一系列语言，整个仓库首页会更像一个有策展感的课程馆

这条 playbook 解决的不是“画一张好看的图”，而是“**先读懂课程，再把课程的学习对象、主流程和气质压成一张 4:3 封面**”。

## 何时适用

- `README.md` 或 `课程/README.md` 里已经有多门课程，想把入口做得更抓眼球
- 课程本身有清晰对象和方法论，不想用泛泛的 AI 海报糊过去
- 希望后续几门课延续同一系列视觉，而不是每门课各画各的
- 需要给即梦图片生成模式准备可直接复制的中文 Prompt

## 何时不必硬套

- 课程还没定名，标题很可能继续改
- 课程定位还很虚，只知道“想做点 AI 学习内容”，还没有明确主对象或主流程
- 只是临时做一张宣传图，不准备纳入知识库长期维护

先把课程定位写稳，再做封面，返工会少很多。

## 先收集什么

至少先看这几样，再写 Prompt：

1. 课程索引里的**一句话注释**  
   先知道这门课到底在学什么。

2. 课程自己的 `README.md`  
   重点抓：
   - 学习对象是谁
   - 这门课的目标是什么
   - lessons / reference 主要围绕什么展开

3. 课程的 `MISSION.md`（如果有）  
   这里通常能读出“成功长什么样”，比 README 更能提炼封面的信息骨架。

4. 课程现有视觉资产  
   例如该课 `assets/course.css`、流程图与速查图。  
   目的不是照抄，而是提取：
   - 主色系
   - 页面气质
   - 结构隐喻（地图、分叉、公路、卡片、清单、表格、节点等）

## 先判断这门课“视觉上到底在讲什么”

不要一上来就写“AI 课程封面、科技感、发光、机器人”。

先把课程压成下面这四个字段：

- **学习对象**：这门课围绕谁或什么展开  
- **主流程**：学习路径是地图、流水线、对照、拆解，还是案例复盘  
- **画面隐喻**：最适合变成封面的视觉骨架是什么  
- **不要什么**：最容易跑偏到哪里

以 `mattpocock-skills 仓库学习课` 为例：

- 学习对象：`mattpocock/skills`
- 主流程：仓库地图 + `ask-matt` 主线 + skill 精读
- 画面隐喻：流程公路、节点并线、仓库地图、信息卡片
- 不要什么：机器人头像、赛博霓虹、泛 AI 海报腔

## 出 Prompt 的默认做法

默认按**即梦图片生成模式**来写，场景档案用 `cover`，比例固定 `4:3`。

README 课程封面有一个默认优先级：

- 先让人一眼看到课程名
- 再让人感到这门课在讲什么
- 最后才补风格和细节

如果课程名本身有辨识度，例如 `Superpowers`、`swarmforge`、`ask-matt`，默认把它当成第一视觉主标题，放大、放正、放稳。副标题只负责解释，不和主标题抢。

标题和主体不是同一个问题。

- 标题系统要稳
- 主体内容要准

如果标题已经稳定，但画面总在乱编无关内容，就不要继续压短 Prompt。此时应该把主体细节写够，让模型知道**到底要画哪条流程、哪组节点、哪几个关系**。

对 Seedream 5.0 Pro 的 agent 模式，较细的主体描述是有价值的。尤其是工程图、流程图、仓库地图这类封面，Prompt 不该只停在“像工程地图”，而要继续写到“地图里具体出现什么”。

Prompt 里至少要同时写清：

1. **封面用途**  
   不是泛生图，而是“知识库 README 课程入口封面”。

2. **保持项**  
   课程核心气质不能丢，例如工程化、地图感、流程感、课件感。

3. **主视觉骨架**  
   课程更像地图、流程图、工作台、卡片阵列，还是单主体海报。

4. **标题系统**  
   如果是封面，标题必须写清：
   - 标题内容
   - 放在哪
   - 单行还是双行
   - 谁主谁辅
   - 字体气质
   - 颜色、底托、描边或微弱光效
   - 与主体的避让关系

5. **负面约束**  
   明确禁止无关文字、错误题材、过度科幻、信息过满。

6. **主体细节**  
   如果这门课靠具体流程、具体节点、具体对照关系成立，Prompt 里要把这些内容写出来，而不是只给抽象氛围词。

## 标题默认怎么处理

做 README 课程封面时，标题系统默认按下面的顺序处理：

1. **先决定谁负责抓眼球**  
   通常是课程名里的核心词、仓库名、作者名、流程名，或这门课里最有辨识度的那个钩子。  
   例如：
   - `Superpowers` 负责抓眼球
   - `skill 学习课` 负责解释
   - `Uncle Bob` / `SwarmForge` 负责抓眼球
   - `工作流课` 负责解释
   - `mattpocock/skills` 负责抓眼球
   - `仓库学习课` 负责解释

2. **不要默认把课程类型词做成最大字**  
   `仓库学习课`、`工作流课`、`skill 学习课`、`项目拆解课` 这类词通常信息价值低，默认不做第一视觉。
   它们负责交代“这是什么课”，不负责把人勾进来。

3. **主标题尽量短**  
   单个词、短词组，或最有辨识度的那一段最稳。  
   标题越长，模型越容易写歪、写错、写散。

4. **主标题默认水平正放**  
   除非用户明确要斜切、贴纸、透视字，否则一律默认：
   - 水平排版
   - 基线平行
   - 不旋转
   - 不透视变形

5. **副标题退后**  
   只用小一号文字交代“仓库学习课”“skill 学习课”“工作流学习课”这类信息。

6. **允许用第二钩子做辅助亮点**  
   如果课程里还有一个明显的流程词或命令词，也可以做成小一号的辅助亮点，但不能抢过主标题。
   例如 `mattpocock/skills` 做主标题，`ask-matt` 可以做次级标签、路牌或流程节点。

## 主体默认怎么处理

标题抓眼球以后，主体要负责“证明这门课真的在讲这个”。

做这类课程封面时，主体默认按下面的顺序细化：

1. **先写抽象骨架**  
   先定这是流程公路、仓库地图、对照矩阵、系统蓝图，还是 pack 流水线。

2. **再写关键内容元素**  
   不是只说“有很多节点”，而是写清：
   - 哪几类节点
   - 哪几条主线
   - 哪些关系最重要
   - 哪些词或标签可以出现

3. **只保留和课程真的相关的细节**  
   细节越多，越要克制范围。  
   不要为了让画面丰富，就让模型自己发明无关仓库、无关模块、无关地名或无关功能词。

4. **优先画课程里反复出现的关系**  
   比如：
   - `mattpocock/skills`：`ask-matt` 主线、上坡入口、主线站点、并线关系
   - `Superpowers`：skills 库、harness 接线、七步工作流
   - `SwarmForge`：`main` 底座、two / four / six pack 流水线

5. **出现跑偏时，加内容白名单和黑名单**  
   白名单写“必须出现什么”，黑名单写“不要出现什么”。  
   例如 `matt` 课可以明确：
   - 需要：`ask-matt`、`grill-with-docs`、`to-spec`、`to-tickets`、`implement`、`code-review`
   - 不要：泛化成仓库村庄、无关业务词、无关 GitHub 功能图解

## 系列封面的统一规则

如果后面还有多门课，第一张图不要只顾当前这门课，也要顺手立住系列规则：

- 比例统一用 `4:3`
- 统一保留一块稳定标题安全区
- 统一一套主色逻辑，但每门课有自己的次级隐喻
- 统一“信息型课程封面”的气质，不突然切成插画风、人物写真风、二次元风
- 除主标题外，不默认加英文副标题、作者名、日期角标、按钮文案

对本知识库来说，一个比较稳的起点是：

- 底色偏米白纸张或浅暖色
- 主色偏深绿、暖棕、低饱和青绿
- 视觉语言偏“课程册 + 信息设计 + 工程地图”

## Prompt 骨架

先写清标题和主体骨架。  
如果这门课的视觉语义很具体，就继续把主体细节补到能锁住方向为止。

```text
这是一个用于 GitHub README 课程入口的 4:3 信息型课程封面。
保持【课程气质 / 学习对象】，不要做成【错误方向】。
主视觉是【画面隐喻】，主体放在【区域】，为标题留出【区域】。
标题为“【主标题】”，作为第一视觉焦点，大字、水平正放、清晰可读；副标题“【副标题】”更小，只做解释。必要时再放一个小一号的辅助钩子“【次级标题】”。
主体里明确出现【关键节点 / 关键关系 / 关键流程 / 关键标签】。
配色参考【主色】；不要【错误元素 / 无关文字 / 角标 / 按钮感】。
```

如果标题已经稳定但图像内容还在跑偏，就继续补主体细节，不要一味缩短。

尤其是这几种情况，要主动写长一点：

- 画面总跑偏到错误题材
- 画面出现大量与课程无关的内容
- 工程图 / 流程图只有气质，没有真正的课程信息
- 用户已经确认标题没问题，只要修主体内容
- 用户明确要求更精细的节点、流程、排版或避让关系

这时再补：

```text
标题必须【水平正放 / 不旋转 / 不透视】。
主体必须出现【白名单内容】。
不要出现【黑名单内容】。
标题与主体保持【避让关系】。
不要【挡脸/压头/裁主体/无关文字/按钮感/科幻霓虹/额外角标】。
```

## 推荐输出物

默认先给：

- `Prompt`

用户明显还会继续改时，再补：

- `理解摘要`
- `注意事项`
- `carry_forward`

其中 `carry_forward` 只保留后续继续生成真正需要的信息，例如：

```yaml
profile: cover
target_ratio: 4:3
series_goal: README 课程可点击封面
palette:
  - 米白纸张
  - 深墨绿
  - 暖棕铜色
visual_language:
  - 信息设计
  - 流程地图
  - 课程册封面
avoid:
  - 机器人头像
  - 赛博霓虹
  - 杂乱小字
```

## 产图后怎样接回 README

如果封面图最终要进知识库首页，别只存图不接入口。

通常做法：

1. 把图片放进 `assets/image/`
2. 文件名按仓库规范使用“日期 + 英文短语”
3. 在 `README.md` 里用图片链接到课程页

示例：

```markdown
[![mattpocock-skills 仓库学习课封面](./assets/image/2026-08-course-cover-matt-skills.png)](<./课程/mattpocock-skills 仓库学习课/README.md>)
```

如果后面要并排展示多门课，再在对应课程标题或说明文案处补普通文本链接，避免只有图片可点。

## 交给 Agent 的指令

---

请先阅读知识库 `playbook/课程封面：给 README 做可点击入口.md`，并按该条目操作。

**任务**：为 `【课程路径】` 生成一份可直接用于即梦图片生成模式的中文封面 Prompt，用于知识库 `README.md` 的课程入口图。

**要求**：

1. 先阅读课程索引条目、课程 `README.md`、`MISSION.md`（如果有）与课程 `assets/` 中最能代表视觉语言的 1–2 个文件，再提炼 Prompt。
2. 封面用途明确写成“README 课程入口封面”，比例固定 `4:3`。
3. 不要产出泛 AI 海报；先提炼这门课的学习对象、主流程、画面隐喻与负面约束。
4. 标题默认优先抓眼球。课程名里有高辨识度词时，优先把这一个词做成大标题；解释性文字退成副标题。
5. 不要默认把“仓库学习课”“工作流课”“skill 学习课”这类课程类型词做成最大字。先找真正能勾住人的词。
6. 先把标题系统写稳，再判断主体是否需要继续细化。标题稳了但主体跑偏时，要主动补足主体细节，不要为了“短”而牺牲准确性。
7. 工程图、流程图、仓库地图类封面，默认要写到关键节点、关键关系和白名单内容，避免模型自己发明无关元素。
8. 除非用户明确要求，否则不要擅自加入英文副标题、作者名、日期角标、按钮文案或额外小字。
9. 默认输出 `Prompt`；用户明显还会继续调时，再补 `理解摘要`、`注意事项` 与最小 `carry_forward`。简体中文回复。

---

## 验收

- [ ] Prompt 读起来像“课程入口封面执行指令”，不是泛生图描述
- [ ] 画面隐喻能对上课程的学习对象和主流程
- [ ] 标题先抓眼球，解释性文字退后
- [ ] 课程类型词没有误当成最大字
- [ ] 标题稳定后，主体细节已经写到足以锁住正确内容
- [ ] 标题系统、留白区和避让关系都已写清
- [ ] 已显式写出不想要的错误方向
- [ ] 后续再做第二门、第三门课时，可以沿用同一系列语言继续生成
