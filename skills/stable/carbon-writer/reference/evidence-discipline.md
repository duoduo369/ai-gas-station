# 证据纪律

只要一篇稿子会碰到“当前技术事实”“行业做法”“社区采用”“谁在怎么用”“今天还值不值得学”这类内容，就别只靠顺手一写。先把证据纪律立住。

## 哪些句子默认需要证据

- 关于当前产品能力、限制、版本差异的判断。
- 关于某种方法今天是否仍被使用、谁在使用、在哪些项目里出现的判断。
- 关于技术社区讨论、作者公开表态、组织实践的判断。
- 关于“这本书 / 这个方法对当下 Agent 编程仍有启发”的外部支撑。

## 可以接受的支撑材料

- 官方文档、官方博客、项目仓库、发布说明。
- 作者访谈、作者文章、作者公开演讲。
- 高信号技术站点、技术组织博客、被广泛引用的讨论。
- 高星 GitHub 项目、相关 skill、真实项目中的公开用法。

## 不够好的支撑

- 只看到一个二手转述，就当成结论。
- 只因为这件事“听起来合理”，就当成现在仍成立。
- 只有一句模糊印象，没有可回看的出处。

## 写作时的落法

- 能给出处的，直接给出处。
- 结论是“由几个事实推出来的”，就把事实和推断分开写。
- 没搜到足够支撑，不要反过来硬凑结论。
- 如果这篇稿子的价值就在于证据成立与否，那证据不够就留空，不要靠文风补齐。
