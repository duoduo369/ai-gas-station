# HKR

HKR 用来筛长稿、判断型文章、深度导读和技术观察值不值得写，不是每一段文字都要硬套的打分器。

## 三个维度

- `H = Happy`
  不是“轻松有趣”这么窄，而是这篇东西里有没有能把人带进去的点。可以是反直觉、具体场景、冲突、荒诞感，也可以是一个很打人的问题。
- `K = Knowledge`
  读完后有没有真的多知道点东西。可以是新信息、新解释框架、新的证据组合，也可以是把一个老话题说清楚。
- `R = Resonance`
  读者会不会觉得“对，这就是我也遇到过的问题”或者“原来我模糊感受到的东西可以这样说出来”。

## 什么时候用

- 用户要写长稿、导读、深度技术观察、资源解读、方法论文章时。
- 你感觉材料够多，但不确定这篇文章值不值得成立时。
- 你已经开始写了，但越写越像“信息堆砌”时。

短说明、短伴读、局部重写不用强行套 HKR。

## 怎么用

先不要问“能不能写满”，先问这篇稿子的主线至少占几项：

- 三项都站得住，可以写长一点。
- 只有两项站得住，可以写，但要收紧角度。
- 只剩一项在撑，通常不要硬写成长稿。先补材料、换 framing，或者缩成短稿。

## 常见修法

- `H` 不够：别拿大词开头，换成更具体的场景、误读、冲突或问题。
- `K` 不够：别再堆判断，回去补事实、证据、例子、反例。
- `R` 不够：别只讲抽象正确，补“这为什么会打到今天的人”。

HKR 不是为了制造“爆款感”，而是为了避免把一篇本该收短、换角度或晚点再写的稿子，硬撑成一篇长文。
