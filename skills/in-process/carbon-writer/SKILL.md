# carbon-writer

为本仓库的课程、学习文章、技术观察、书籍导读、资源解读等非虚构场景起草或重写稿件。
目标不是把文字写得“像会写”，而是写出判断清楚、证据边界明确、中文自然的成品。

## Before you start

- 先读 [`./reference/nonfiction-checklist.md`](./reference/nonfiction-checklist.md)。
- 先读 [`./reference/ai-boundary.md`](./reference/ai-boundary.md)，先把“AI 能做什么、不能硬编什么、哪些东西必须来自人或证据”分清。
- 先读 [`./reference/review-layers.md`](./reference/review-layers.md)，把硬约束、结构推进、证据边界和活人感终审分层看，不要混成一句“再润色一下”。
- 先确认场景真的属于本仓库的非虚构写作；具体适用范围与排除项都以 checklist 为准，不在主文件里重复展开。
- 先锁定入口模式：`from-scratch`（从材料起稿）或 `rewrite`（重写现有草稿）。
- 如果这次是长稿、判断密度高的稿子，或带明显“选题 / 观点 / evidence”压力的稿子，再读：
  - [`./reference/hkr.md`](./reference/hkr.md)
  - [`./reference/evidence-discipline.md`](./reference/evidence-discipline.md)
- 如果是书籍导读、资源解读这类伴读型内容，再读 [`./reference/book-guide.md`](./reference/book-guide.md)，不把它写成抽象书评。

## Steps

1. 压实这次写作的最小输入。
   完成标准：至少已经拿到主题、目标读者、这篇为什么现在要写、这篇要成立的判断、现有材料或旧稿之一；如果还要写长稿，再补够最少的真实材料。输入太薄时，只追问 1-3 个缺口，或者把产出缩到更小。
2. 先判断这篇东西值不值得这样写。
   完成标准：长稿、深度导读、判断型技术文章已经按 [`./reference/hkr.md`](./reference/hkr.md) 过过一遍；如果 `H / K / R` 里只剩单项在撑，就先缩题、换角度，或回到补材料，而不是直接硬写。
3. 按入口模式搭骨架，并先把证据边界标出来。
   完成标准：`from-scratch` 已经决定“先列提纲”还是“直接起短稿”；`rewrite` 已经判断问题是词句层还是结构层，并且明确允许替换弱标题、重排段落顺序、重写 framing。凡是会被读者当成事实、现状判断、行业用法或他人实践的内容，已经先区分为“有证据支撑”“只是作者判断”“只是推断”。
4. 写出新稿，不替材料和判断胡编。
   完成标准：段落里已经能看到具体事实、场景、对比或作者判断；空泛解释、假细节、套模板推进被删掉；不用生造短语、翻案腔和“作者代言人”口吻去制造判断感；需要重写时，以更好的标题和结构为准，不被原稿绑住。
5. 用分层审校收尾并再改一轮。
   完成标准：已经按 [`./reference/review-layers.md`](./reference/review-layers.md) 走完硬约束、结构推进、证据边界和活人感终审；最后再按 [`./reference/nonfiction-checklist.md`](./reference/nonfiction-checklist.md) 扫一遍中文自然度与坏味道。没过的地方已经继续改，不把问题留在说明里。

## Finish

- 确认成品保住了作者自己的判断和语气，而不是被磨成平衡但空的说明文。
- 确认材料不够时没有硬撑长稿；要么补材料，要么明确缩 scope。
- 确认标题、开头和段落推进都服务这篇文章本身，而不是沿用原稿里更弱的说法。
- 确认文里所有“像事实”的句子，都已经被妥善放回事实、判断或推断各自该在的位置。
