# 记录与协作规范

> 本文件定义第一版仓库的记录方式、命名规则、链接规则和附件规则。
> 冲突时以已关闭的 wayfinder ticket 结论为准。

## 结构

- 第一版采用“对象目录 + 横切目录”的混合结构。
- 对象目录只有：`书籍/`、`演讲/`、`技能/`。
- 横切目录保留：`playbook/`、`assets/`、`docs/`。
- 不额外建立 `资源/` 作为总索引层；对象目录自己承载索引和深度笔记。

## 命名

- 对象目录使用中文命名。
- 对象目录中的索引文件固定命名为 `README.md`。
- 正文文件默认直接使用自然中文标题。
- 只有在同名冲突或确实需要表达时间语义时，才给正文文件加日期前缀。
- 机制性目录保留英文：`playbook/`、`assets/`、`docs/`。

## 索引与正文

- 每个对象目录的 `README.md` 是该目录的人类入口和 AI 快速路由入口。
- `README.md` 顶部允许有 3–8 行策展说明，说明“收什么、不收什么、怎么用”。
- `README.md` 主体按主题分小节组织，不采用纯扁平列表，也不按状态分区。
- 每条索引条目最少包含：
  - 名称
  - 一句话注释
- 每条索引条目可选包含：
  - 原始链接
  - 本地笔记链接
- 只有在已经形成明确学习收获、摘录或实践记录时，才单开正文文件；否则只保留索引条目。

## 链接

- 本地引用统一使用标准 Markdown 相对路径链接，如 `[学习笔记](./把时间当作朋友.md)`。
- 不依赖 Obsidian 双链承载关键结构。
- 不对尚不存在的文件或目录预先加 Markdown 链接。
- 目标尚不存在时，用纯文本或“待补”提示代替，避免 Obsidian 误建空文件。
- 在子目录中写链接时，始终使用显式相对路径前缀：`./` 或 `../`。

## 附件

- 功能性截图、PDF、讲义等统一放在 `assets/`。
- 第一版 `assets/` 不做子目录拆分，先全部平铺。
- 附件文件名采用“日期 + 英文短语”的方式，例如 `2026-08-obsidian-plugin-screenshot.png`。
- 附件是补充材料，不替代正文内容。

## GitHub 与 Obsidian 兼容

- 优先使用标准 Markdown，保证 GitHub 可直接阅读。
- 目录名和正文文件名对人友好，索引和机制文件对工具友好。
- 结构是否扩展，优先走 [wayfinder 地图](./wayfinder/MAP.md)，不要直接在仓库里无约束增目录。
