# T-003 命名、链接与附件规范

## Question

在顶层结构和索引契约明确后，本仓库的命名、链接和附件规范要如何统一？

这张票要回答：

- 中文目录、中文正文文件、固定 `README.md` 之间如何搭配；
- 哪些术语保留英文，例如 `playbook/`、`assets/`；
- Obsidian 下如何避免坏链接、误建空文件、路径混乱；
- 功能性附件进入 `assets/` 时如何命名、如何引用。

## Resolution

第一版命名、链接与附件规范采用“内容中文优先、机制英文保留、链接与附件尽量标准化”的组合策略。

- 对象目录内的正文文件名默认直接使用自然中文标题，例如 `把时间当作朋友.md`。
- 只有在**同名冲突**或**确实需要表达时间语义**时，才给正文文件加日期前缀；不把日期前缀作为默认规则。
- 对象目录中的索引文件固定为 `README.md`，不改成中文文件名。
- 本地链接统一使用**标准 Markdown 相对路径链接**，例如 `[学习笔记](./把时间当作朋友.md)`；不依赖 Obsidian 双链作为机器关键引用。
- 对于**尚不存在**的正文文件或目标，不预先写 Markdown 链接，只保留纯文本或“待补”提示，避免 Obsidian 误建空文件。
- 少数机制性目录保留英文：`playbook/`、`assets/`、`docs/`。
- `assets/` 用于存放功能性截图、PDF、讲义等补充材料；第一版不做子目录拆分，先全部平铺。
- `assets/` 内文件名采用“日期 + 英文/拼音短语”的方式，例如 `2026-08-obsidian-plugin-screenshot.png`，优先稳定与跨平台兼容，而不是中文自然名。

由此形成的第一版实践原则是：

1. 内容对人友好：对象目录和正文文件中文优先；
2. 机制对工具友好：索引、规范、附件等关键基础设施尽量使用稳定规则；
3. 不为未来文件预铺链接，避免空文件和坏链接污染仓库。
