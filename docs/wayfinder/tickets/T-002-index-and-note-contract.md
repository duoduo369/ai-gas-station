# T-002 对象目录的索引与正文契约

## Question

每个对象目录内部，`README.md` 和同目录深度笔记之间的契约到底是什么？

这张票要回答：

- `README.md` 至少要记录哪些字段，例如名称、原始链接、简短注释、本地学习文档链接；
- awesome 风格索引的组织粒度是什么，是单纯列表，还是分主题/分状态；
- 同目录深度笔记如何命名、何时创建、何时只保留索引条目不单开文档；
- GitHub 浏览与 Obsidian 浏览要如何同时保持顺手。

## Resolution

第一版对象目录内部采用“README 索引 + 同目录深度笔记”的轻量契约。

- 每个对象目录的 `README.md` 顶部允许有一小段策展说明，说明“这个目录收什么、不收什么、怎么用”，控制在 3–8 行。
- README 主体按**主题分小节**组织，而不是纯扁平列表或按状态分区。
- 每条索引的最小字段为：
  - 名称
  - 原始链接（可选）
  - 一句话注释
  - 本地笔记链接（可选）
- 原始链接不是必填项。对于 `技能/` 这类更多来自个人实践的内容，只要“名称 + 注释”成立，就可以进入索引。
- 并非每条索引都要单独建正文文件。**只有当自己已经形成明确学习收获、摘录、实践记录时，才单开深度笔记**；否则只保留索引条目。
- 深度笔记与 README 放在同一目录内，由 README 回链，保持 Obsidian 与 GitHub 浏览路径一致。

由此形成的第一版目录内模型是：

1. `README.md` = 人类入口 + AI 快速路由入口；
2. 索引条目 = awesome 风格的轻量记录；
3. 深度笔记 = 只为真正发生了沉淀的对象而存在。
