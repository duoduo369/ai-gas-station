# T-007 `skills/` 学习文档的自包含附录契约

## Question

当 `skills/` 下为某个具体 skill 单开学习文档时，正文是否应该做到“自包含”？如果要自包含，边界和写法应该是什么？

这张票要回答：

- 用户只打开单篇学习文档时，是否应该不用再来回跳索引和外部仓库，也能看懂对象、原文与本地理解；
- `skills/` 学习文档顶部是否要提供到原始 skill、目录索引、文内附录的快速跳转；
- 原始 `SKILL.md` 的内容和中文版本是否应沉到文末附录；
- Obsidian 与 GitHub 下，文内跳转用什么机制最稳。

## Resolution

结论：`skills/` 下已经单开的具体 skill 学习文档，默认采用“**顶部导航 + 主体拆解 + 底部附录**”的自包含结构。

- 这里的“自包含”指：用户只打开这一篇文档，也能顺手完成四件事：
  - 知道当前在学哪个 skill；
  - 一键回到原始 skill；
  - 一键跳到本地整理出的原文附录与中文附录；
  - 在不离开当前文档的情况下，对照原文和自己的学习拆解。
- 每篇具体 skill 学习文档在标题下方默认补一段导航区，最少包含：
  - 原始 skill 链接；
  - 回到 `skills/README.md` 的索引链接；
  - 指向文末附录的文内跳转链接。
- 文内跳转采用**稳定锚点**而不是依赖平台各自的标题 slug 规则：
  - 在文末附录标题前放显式锚点，例如 `<a id="skill-source-md"></a>`、`<a id="skill-source-zh"></a>`；
  - 在文首导航区使用 `[跳到原文附录](#skill-source-md)`、`[跳到中文附录](#skill-source-zh)`；
  - 这样在 Obsidian 与 GitHub 中都更稳定，不必赌中文标题或标点被如何转 slug。
- 文末附录默认采用两段：
  1. `附录 A：原始 SKILL.md`
  2. `附录 B：中文翻译`
- 若原始 skill 不是中文，则默认补中文翻译附录；翻译应尽量保持原文结构对应，方便上下对照。
- 为避免正文被附录淹没，主体学习拆解仍放在前半部分；附录统一沉到底部，不插回正文中段。
- 若附录较长，可在附录标题下再用 `<details>` 包裹正文，但锚点与附录标题本身应保持可见，确保顶部跳转仍然落到正确位置。
- 既有文档允许渐进式补齐，不要求一次性全量回填；但此后新建或大修的具体 skill 学习文档，默认按这套契约执行。

由此形成的第二层目录内实践是：

1. `skills/README.md` 负责索引和分组；
2. 单篇学习文档负责学习拆解与自包含附录；
3. 原始 skill 与中文版本都能在单文档内被回看，而不必依赖外部页面或额外搜索。
