# T-001 顶层目录结构与边界

## Question

在“对象类型为主 + 横切目录补充”的前提下，第一版仓库到底有哪些顶层目录？

这张票要回答：

- 哪些目录属于对象类型目录，如 `书籍/`、`演讲/`、`技能/`；
- 哪些目录属于横切目录，如 `playbook/`、`assets/`、`docs/`、`misc/`；
- `资源/` 是否需要作为独立顶层存在，还是由对象目录自己承载“awesome 风格索引 + 深度笔记”；
- 第一版明确不做哪些目录，避免过早铺开。

建议通过一个粗目录树原型来对齐，而不是只停留在口头描述。

## Resolution

结论采用粗目录树原型中的“轻量混合”思路，但进一步收紧为更克制的第一版：

- 顶层以**对象目录 + 横切目录**组织，而不是 `资源/知识` 分层。
- 第一版对象目录只保留：`书籍/`、`演讲/`、`技能/`。
- 第一版横切目录保留：`playbook/`、`assets/`、`docs/`。
- **不建**顶层 `资源/`：对象目录自身承载 awesome 风格索引与同目录深度笔记，避免重复索引层。
- **不建** `收件箱/`：用户更倾向依赖 Obsidian 侧已有默认机制，而不是在仓库里单列缓冲目录。
- **不建** `主题/`：等未来真实内容反复出现，再决定是否升格为新对象目录或横切目录。

配套原型见：[T-001 粗目录树原型](../prototypes/T-001-top-level-structure-prototype.md)。
