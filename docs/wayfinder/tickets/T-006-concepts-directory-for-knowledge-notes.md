# T-006 为概念性知识点新增顶层对象目录

## Question

当内容已经形成明确沉淀，但又不适合挂在 `书籍/`、`演讲/`、`skills/` 下时，仓库是否需要新增一个顶层对象目录来承接这类概念性知识点？

这张票要回答：

- `agent 是什么`、`token 是什么`、`skill 的作用域` 这类内容，是否应该有独立归属；
- 新目录应命名为 `概念/`、`知识/`，还是别的名字；
- 它和 `skills/`、`playbook/` 的边界分别是什么；
- 已经从具体 skill 学习外溢出来的文档，是否应该迁到新目录。

## Resolution

结论：新增顶层对象目录 `概念/`，用于承接**不依附于单一本书、演讲或 skill，但值得长期保留的概念解释、术语拆解与机制理解**。

- 对象目录从 `书籍/`、`演讲/`、`skills/` 扩展为 `书籍/`、`演讲/`、`skills/`、`概念/`。
- 目录名采用 `概念/`，**不采用** `知识/`：
  - `知识` 在当前仓库语言里范围过大，容易把结构重新拉回“资源/知识”二分；
  - `概念` 更准确地指向这类“解释一个概念、术语、机制”的沉淀。
- `概念/` 的边界：
  - 收录 AI 概念、术语、机制、作用域、成本模型等解释性内容；
  - 不要求绑定单一外部资源；
  - 不要求已经上升为可复用方法。
- `skills/` 的边界保持收紧：
  - 只收与 agent skills 直接相关的学习、拆解、实践与复盘；
  - 如果一篇文档的重心已经从“某个 skill 本身”转向“跨多个 skill 的概念或方法框架”，应迁入 `概念/`。
- `playbook/` 的边界不变：
  - 只收已验证、可重复复用的方法、流程、套路；
  - 解释概念但还不是方法的内容，不进入 `playbook/`。
- 配套动作：
  - 初始化 `概念/README.md` 作为索引入口；
  - 将已经更适合概念层的 [skill 的作用域与放置](../../概念/skill%20%E7%9A%84%E4%BD%9C%E7%94%A8%E5%9F%9F%E4%B8%8E%E6%94%BE%E7%BD%AE.md) 迁入 `概念/`。
